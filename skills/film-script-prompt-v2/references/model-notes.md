# Seedance 2.5：资料依据与能力边界

用于判断模式、输入、时长或能力；普通写稿不必将整份参数表展示给用户。

## 本版采用的结构、声音与时长规划

以下依据用户2026-11-07对“影视脚本提示词2.0”的要求，属于本版写作规则，不冒充模型官方语法或新做的能力实测：

- 每个独立提交的生成段均按【素材绑定】【视觉风格锁定】【画面描述】【负面提示词】输出，声音写在画面描述中。正文、任务路径和示例统一遵循该结构。
- 新建内容在用户未明确要求时，不添加背景音乐；可按画面配置环境声与音效。配乐默认在后期剪辑时统一处理。视频局部编辑保留未要求改变的原声。
- 按单次生成4—30秒规划，常规优先低于25秒；25—30秒用于确有动作连续、特殊过渡或较高衔接要求的内容，最长30秒。
- 一次生成可以包含多个镜头。单次总长、段内单镜时长和全片总长分别计算，不把25秒以下写成每镜接近20秒，也不把单次4秒下限套给段内镜头。
- 下文超长模式是旧手册的历史记录；本版较长全片按上述规则分段，不自动规划一次生成30秒以上。实际执行仍需核对对应入口。

## 创作路径

手册记录模型可接收文本、图像、视频和音频，支持仅传音频。应先选任务，再给每份素材分工。

| 路径 | 写作重点 | 注意事项 |
|---|---|---|
| 纯文本／全能参考新建 | 外观、动作、空间、运镜、声音的职责 | 无参考也能写；无需强凑素材 |
| 首帧／首尾帧 | 起点、终点及中间变化 | 把画面终态与动作连接起来；实际入口需支持 |
| 超长视频 | 覆盖全片的脚本和持续身份 | 网页独立模式，不等于所有入口的常规时长 |
| 视频延长 | 原片末态之后的新增内容 | 新增时长与总时长分别计算 |
| 智能编辑 | 修改对象、方式、时间与保留项 | 上传视频后可用高级编辑定位；生成流另有视频编辑入口 |
| 白模控制 | 映射几何体、保留运动或空间，替换外观 | 可精确限定只参考某一方面或某一时段 |
| 两段衔接 | 前段末态→过渡→后段起态 | “保留原片”是目标，不能承诺逐帧不变 |

截图出现“智能多帧”，正文未给独立规则；不要自行补写其使用方法。白模章节提及 Maya／Blender 插件，没有完整安装说明或 C4D 兼容性证据。

## 时长与输出：分清三个语境

| 语境 | 手册快照记录 | 提示词处理 |
|---|---|---|
| 常规参数表 | `duration` 为 `-1` 或 4—30 秒；表内写 97—721 帧 | `-1` 含义未解释，不自行解释；不据帧数推定实际固定帧率 |
| 网页超长视频 | 完整成片 30—180 秒 | 历史独立模式记录；本版较长全片仍按单次不超过30秒分段，不当作常规单次设置 |
| 网页视频延长 | 底片≤30秒；单次新增4—30秒；总长≤60秒 | 只写新增段，连续延长引用最新完整结果；底片超过30秒后不能据此继续无上限延长 |
| 输出分辨率参数表 | 480p、720p | 截图720P和正文720P+不证明所有模式统一支持720P+ |

用户在 LibTV、Tapnow 等平台使用时，不将即梦网页的 180 秒能力直接移植为该入口参数。平台暂不明确时可先完成脚本，把模式或规格标为需核对，不必阻止全部创作。

提示词中的“4K、8K、60fps、Octane渲染”只能作为视觉或效果诉求，不能取代生成参数或证明导出规格。需要真实规格时用平台设置和实际文件核验。

时间戳是动作和镜头安排，不是逐帧调度程序。手册对案例写的是“基本符合秒级范围”；其中“720帧=24秒”是单条脚本的30fps标法，不是平台帧率承诺。

原例也混用时间区间与离散事件点；只标“第2.1秒开始横移”并不意味着其他时刻没有画面。`@图一`、`@图片1`、`@参考图1` 或案例中的 `@音效2` 是引用称呼差异，不证明存在不同功能或独立音效上传类型；应沿用入口真实标签。

## 参考素材：上限与建议分开

以下为手册快照；用于素材准备建议，不默认展开到每次提示词交付。

| 素材 | 记录的数量与时长 | 补充 |
|---|---|---|
| 图片 | ≤30张 | 建议表写4K以内；另有单张<30MB、请求体≤64MB |
| 视频 | ≤10段；每段2—30秒；全部视频合计≤30秒 | mp4/mov，480p—4K，24—60fps，单段≤200MB |
| 音频 | ≤10段；每段2—30秒；全部音频合计≤30秒 | wav/mp3，单段≤15MB、请求体≤64MB；可仅传音频 |

视频和音频的合计限制分别计算。手册列出的 30.2 秒属于接收容差，不作为常规准备目标。上传提示“最多50个参考素材”不覆盖各类上限。

手册格式、尺寸和请求体部分来自跨版本共用单元格，标题仍写“适用于Seedance 2.0系列”；不能当成独立验证的2.5专用协议。完整文件兼容性或API请求校验需要时再查原表或当前接口，不在提示词里模拟上传。

稳定性建议属于经验范围：

- 含主体的音／视频：1—5个主体、5—10秒更稳；6—10个主体可尝试。
- 主体图：1—8个主体较稳；9—12个可尝试。超过5个主体时单视图通常更稳；多视角可拆成多张，减少一图多角度混淆。
- 编辑视频建议≤20秒；参考图1—5张较稳，6—8张可尝试。
- 这些建议不是硬上限，不以此否决用户已指定的人数、时长或素材方案。

## 不应误学的案例问题

| 原例问题 | 写作时怎样处理 |
|---|---|
| 午后／雨夜；只要白噪音／又要钢琴BGM | 统一时间、光线和声音目标 |
| 25秒／15秒；延长10秒／栏位15秒 | 以用户明确目标算清时间，再修改冲突 |
| 保留版面编号／禁止所有文字 | 规定保留文字及禁止新增文字的范围 |
| 全局马来语／分镜英语和西班牙语 | 指令语言、对白、画内文字逐项绑定 |
| 叉形武器／剑；黑盖／银盖；无花果／芭乐 | 按已确认素材和用户意图统一，不继承原稿笔误 |
| 角色图编号与他／她不对应 | 建立稳定的角色编号与行为对应 |
| 0—5、6—10秒等连续区间有空档 | 改为连续边界；除非明确是有意停顿 |
| 原图8格、脚本9镜；中年女人／老人混称 | 说明是否扩展脚本，保持人物年龄和身份一致 |

手册里“无损分离”“完美一致”等强表述不能成为效果保证；2.0 对比列的失败也不能当作2.5的实测失败。第7章的观察应称为原件整理者观察，不称为本 Skill 亲自测试。
